# EasyConnect 1.0 连线功能需求分析（修订版）

## 1. 功能定位与基本模型

以 `docs/1.0版本需求文档.md` 为需求基准，根据建图 JSON 修改 RTL，支持连接的增加、删除和修改。

用户通过 **module 名**指定起止模块，通过**例化位置选择**确定连接路径。实际修改包括 module 定义，以及父模块中的例化语句。

- 每条连接选择一条源例化语句和一条目标例化语句；一源多目标通过多次 `add` 完成。
- 多个实例共用原 module 定义，不复制模块。
- “分开”表示选择不同例化位置分别接线。
- 修改共用父模块内部的连线，会作用于该父模块的所有实例；预览展示影响范围。
- 同一 module 被不同父模块类型例化的路径处理暂不支持；涉及该情况时明确报告，不任意选择父模块。

## 2. 起止信号与路径生成

### 2.1 源信号规则——本次修订

**执行 `add` 时，源信号可以不存在；不存在则自动生成 wire，并将其作为连接的源信号导出。**

| 源信号状态 | 处理方式 |
|---|---|
| 不存在 | 新建 wire，并补充导出端口 |
| 已有兼容 wire、reg 或 logic | 复用声明，保留原类型及业务逻辑，补充必要的导出端口 |
| 已有兼容 output | 直接复用 |
| 存在无法兼容的同名声明 | 报告冲突，不覆盖原声明 |

新建 wire 后，工具不自动添加业务驱动，也不默认将源信号接零。用户可以先搭建连线，再补充驱动逻辑；预览标明“本次新建、待用户驱动”。

源码生成遵循原模块端口风格。例如 ANSI 风格可以合并声明：

```verilog
module SRC (
    // 原有端口
    output wire sig
);
    // sig 的业务驱动由用户后续补充
endmodule
```

这里 `output wire sig` 同时完成 wire 声明与端口导出，不再重复生成 `wire sig;`。

### 2.2 目标信号规则

- 目标不存在：新建 input。
- 已有兼容 input：复用。
- 已有内部信号：通过必要的辅助 input 和连接赋值接入，保留原声明。
- 目标已有不同端口绑定或可识别的驱动冲突：拒绝覆盖。
- 同名端口无法承担所需方向时，使用以连接 ID 命名的辅助端口，并在预览中展示。
- 工具不自动编写源端驱动逻辑或目标端业务逻辑。

### 2.3 四种路径角色

```text
A
├── U_B：B
│   └── U_C：C，源 src_name
└── U_D：D，目标 dst_name
```

| 角色 | 修改规则 |
|---|---|
| 开始 | 在源模块创建或复用源信号，补充或复用 output |
| 向上链接 | 中间模块增加 output，连接下级 output |
| 转向 | 最近公共祖先声明 wire，连接两侧例化 |
| 向下链接 | 中间模块增加 input，将输入传给下级 |
| 结束 | 在目标模块创建 input，或接入兼容的已有信号 |

源侧沿途使用 `src_name`，目标侧沿途使用 `dst_name`。名称转换集中在转向模块：

```verilog
wire w_src_name;

B U_B (..., .src_name(w_src_name));
D U_D (..., .dst_name(w_src_name));
```

特殊路径：

- 源是目标的祖先：直接向下传递。
- 目标是源的祖先：向上传递；缺失目标默认创建 output，支持顶层导出。
- 两端位于同一选定模块作用域：使用局部连接；缺失目标默认创建局部 wire。
- 两端是同类型模块的不同实例：经过父模块连接。
- 两端完全相同：报告无需连线，不新增记录。
- 路径有歧义：交互选择；不存在共同层级入口时拒绝。

## 3. 多次例化、索引与宽度

### 3.1 多次例化

通过父模块、例化名和文件位置展示候选，由用户选择。

修改共用 module 后：

- 选中实例按规划接线。
- 未选实例的新增 input 显式接全零，新增 output 显式悬空。
- 已有端口绑定保持。
- 后续连接可以替换工具此前生成的默认接零或悬空。
- 同一源的多条连接复用兼容的端口和线网。
- 同一目标不能被不同源重复占用。

共用父模块内部的修改统一作用于其所有实例。影响范围按源码引用关系展示，不统计循环展开后的数量。

### 3.2 for / generate 与方括号

本版不寻找、不识别、不展开 `for/generate`，也不据此进行多驱动提示或索引检查。只修改可定位的例化语句，保留周围原文。

`MODULE.sig[i]` 中：

- 子模块端口名为 `sig`。
- `[i]` 表示直接父模块中的绑定下标。
- 生成 `.sig(sig[i])`。
- 向更高层传递时使用整根总线，不将 `i` 自动带出原位置。
- 用户负责索引作用域、循环次数及实际驱动关系。

不自动生成拼接、归约、仲裁或 lane 配对逻辑。

### 3.3 维度与位宽

```text
-d：packed 维数
-w：各维大小列表
```

例如：

```text
-d 2 -w 'a,b'
```

生成：

```verilog
wire [a -1:0][b -1:0] sig;
```

规则：

- 默认一维一位，生成标量。
- 只提供 `-w` 时，由列表长度推导维数。
- 同时提供 `-d/-w` 时，两者必须一致。
- `-d` 大于 1 时，必须提供各维大小。
- 新生成维度均位于信号名前，不新增 unpacked 数组路由能力。
- 宏和参数表达式原样保留，用户保证跨模块可见性。
- `-w` 描述父层及中间层传输总线的形状。

**新建源信号的形状：**

- 源不带下标：按传输总线形状创建 wire。
- 源带下标：按总线被选择后的形状创建 wire。
- 源已存在：保留已有形状，核验可确定的兼容性。

例如：

```text
add SRC.sig[i] DST.recv -w 8
```

若两端均不存在：

```verilog
// SRC：新建并导出 1 bit wire
output wire sig;

// SRC 的直接父层：8 bit 总线
wire [8 -1:0] sig;
SRC U_SRC (..., .sig(sig[i]));

// DST：接收整根 8 bit 总线
input wire [8 -1:0] recv;
```

目标写 `DST.recv[j]` 时，目标父层生成 `.recv(recv[j])`，新建目标端口为 1 bit。

连续 `[i][j]` 按顺序选择 packed 维度。无法确定新建声明形状时报告错误，不猜测；可确定的形状不匹配时拒绝，不自动截断或扩展。

## 4. 命令、执行流程与连接管理

保留单入口和模式编号：

```text
python EasyConnect.py 1 <rtl_folder> <top>
python EasyConnect.py 2 <json_file> add <src_module>.<signal> <dst_module>.<signal> [选项]
python EasyConnect.py 2 <json_file> rm <connection_id>
python EasyConnect.py 2 <json_file> mv <connection_id> [修改选项]
```

每条连接拥有独立 ID。`mv` 可以修改源、目标、信号名称、宽度、维度和注释；未提供的属性沿用原值，ID 保持。

执行流程：

1. 核验 JSON 与当前 RTL 的对应关系。
2. 根据 module 名和例化位置确定路径。
3. 规划端口、wire、绑定及共用定义影响。
4. 检查声明、连接占用和可确定的形状冲突。
5. 展示路径、影响范围、新建未驱动源信号和 diff；`--dry-run` 不写入。
6. 统一提交修改；失败恢复此次操作前的状态。
7. 保存连接归属信息，并刷新受影响的建图位置。

`-c` 注释附在本次新生成的声明、赋值和端口绑定后，不覆盖原有注释。

删除与修改规则：

- 只清理工具生成且不再被其他连接使用的内容。
- 用户原有声明、连接及业务逻辑必须保留。
- 新建源 wire 纳入连接管理；最后一个引用删除后，仅在该 wire 仍未被人工使用或修改时清理。
- 若用户后续为新建源补充驱动，删除连接时保留源信号及业务逻辑；无法确定能否安全清理时保留并提示。
- 共用端口和线网记录引用关系。
- 默认接零、悬空及被替换的原绑定均记录，以便恢复。
- 受管片段被人工修改时，拒绝覆盖并报告差异。
- `mv` 重新规划整条连接，失败时旧连接保持。

建图 JSON 保留 `modules → instantiations` 和 `module/instance/style/status` 四字段，补充源码位置和校验信息。`style/status` 按 1.0 固定为 `normal`，行号不作为唯一编辑依据。

## 5. 验收与默认边界

所有测试在 `test_result/` 副本中完成，跨 case 库依赖一并复制；`test_cases/` 内容必须保持不变。

重点验收：

| 场景 | 预期 |
|---|---|
| add 的源不存在 | 自动创建 wire 并导出，不添加业务驱动 |
| 源已存在 | 复用声明，不重复创建、不破坏原驱动 |
| 缺失源带 `[i]`、传输总线为 8 bit | 创建 1 bit 源，父层绑定总线对应位 |
| 普通跨层、祖先端点、同作用域 | 正确生成或缩短路径 |
| 同父多实例 | 可分别接线，其余新增输入接零、输出悬空 |
| 共用父模块 | 明确展示定义级修改影响 |
| 循环原文中的例化 | 仅编辑例化，不分析循环 |
| 多维、宏表达式及形状冲突 | 按约定生成或明确拒绝 |
| 一源多目标、删除单条连接 | 保留其他连接及共用资源 |
| 新建源后人工补充驱动，再删除连接 | 保留用户使用的源信号及驱动 |
| 修改失败、位置记录失效 | 不产生部分修改，不使用过期位置写入 |
| 三个 case 的建图输出 | 可由现有 `hierarchy_to_html.py` 读取 |

默认仅编辑显式命名端口连接。路径上需要修改位置式连接或无法可靠定位的结构时明确拒绝，不要求整个工程都采用受支持语法。

工具采用 Python 标准库。编译器用于可选开发验收；源码编辑成功与 RTL 编译通过分别报告。
