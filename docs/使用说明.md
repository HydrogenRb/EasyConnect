# EasyConnect 1.0

实现基准为 `docs/1.0版本需求文档.md`，连线细则采用其引用的 `docs/1.0连线功能PLAN.md`。运行时只使用 Python 标准库，支持 Python 3.8 及以上版本。

三个核心脚本：

| 文件 | 职责 |
| --- | --- |
| `EasyConnect.py` | 唯一用户命令行入口，参数检查、建图和连线调度 |
| `RTLGraph.py` | 递归扫描、编译输入读取、源码解析、层级 JSON 和源码校验 |
| `WireConnect.py` | 实例选择、路径规划、冲突检查、diff、事务提交和连接归属管理 |

## 建图

```powershell
python EasyConnect.py 1 ./rtl TOP -o ./hierarchy.json
```

递归搜索 `.v`、`.sv`。自动读取输入目录中的 `filelist.f`；输入目录名为 `rtl` 时，也会查找父目录的 `filelist.f`。支持其中的相对路径、外部库文件、`-f/-F` 子列表、`-I`、`-y`、`-v`、`+incdir+` 和 `+define+`，并解析 include 依赖及 `ifdef/ifndef/elsif/else/endif`。额外编译配置可以显式提供：

```powershell
python EasyConnect.py 1 ./rtl TOP -o ./hierarchy.json -f ./compile.f -I ./include -D FEATURE=1
```

工具生成源码引用图，不做完整编译或 elaboration。宏宽度表达式原样保留，常量兼容性检查会解析可确定的整数宏、参数及显式例化参数覆盖。宏展开产生的模块名、例化语句，以及同一源码在不同宏上下文中产生不同定义的情况，不属于本版可靠编辑范围。

建图采用两遍逐文件扫描：先用正则识别 module 定义，再匹配各模块体内已知模块的例化语句，提取实例名、参数和端口连接。出现模块名还需要符合例化语法才会建立关系；注释、字符串和同名前缀不会生成引用。括号配对只用于模块头、例化参数和连接列表，不对全部 RTL 做语法校验。嵌套函数调用、拼接和重复拼接由局部括号配对处理，避免用正则在第一个右括号处截断信号列表。运行不联网，不需要安装解析器或编译器。

解析错误会显示原文件路径、从 1 开始的行列、模块名和带 `^` 的源码片段，例如 `top.v:3:15 [module TOP]: 括号不匹配: ]`。字符偏移始终对应单个原文件。缺失 include 和错误条件编译指令也会定位到指令所在行。

JSON 保留 `modules → instantiations` 和 `module/instance/style/status` 四字段；`style/status` 固定为 `normal`。同时记录文件、端口区域和例化的起止行号、字符位置及源码 SHA-256。非 ANSI 模块记录实际 input/output 声明的行号。只列出扫描到的模块之间的例化，不分析未知模块。

模块的 `ports` 列出识别到的端口名，例化的 `connections` 保存信号列表：显式命名连接为 `{端口名: 表达式}`，位置连接为表达式列表。简写 `.port` 和通配符 `.*` 标记为 `named_ports: false`，连线时仍要求显式命名连接。

可使用原有可视化脚本：

```powershell
python test_cases/test_python/hierarchy_to_html.py hierarchy.json -o hierarchy.html --top TOP
```

## 增加连接

```powershell
python EasyConnect.py 2 hierarchy.json add SRC.fifo_rd DST.fifo_rd_in
python EasyConnect.py 2 hierarchy.json add SRC.data DST.recv -w 8 -c "debug bus"
python EasyConnect.py 2 hierarchy.json add SRC.data DST.recv -d 2 -w "a,b" --dry-run
```

默认一维一位，生成标量；只给 `-w` 时根据逗号列表推导维数。给出 `-d` 时必须与各维大小列表一致。多维声明生成 `[a -1:0][b -1:0]`，维度全部位于信号名前。

源不存在时自动创建 wire 并在必要时导出 output，同时提示“本次新建、待用户驱动”。工具不添加源端业务驱动或目标端业务逻辑。已有兼容 output/input 会复用；已有内部声明及逻辑保持原文，通过 `ec_<连接ID>_<信号>_out/in` 辅助端口和 assign 接入。辅助端口沿用原信号的 packed 范围，保留参数化宽度。无法确认安全的类型、unpacked 数组或冲突声明会拒绝编辑。

普通跨层连接在源侧生成 output、目标侧生成 input，最近公共祖先生成 `w_<源信号>`，在这里转换端口名称。支持祖先端点、顶层导出、同作用域局部连接，以及同类型模块的不同实例。

端点可以使用 module 名，也可以使用可唯一识别的例化名，例如 `U_SRC.sig`。

### 选择例化位置

同一 module 有多个引用位置时，交互终端会列出候选及文件行号，要求选择。脚本、流水线等非交互场景请显式指定位置：

```powershell
python EasyConnect.py 2 hierarchy.json add SRC.sig DST.recv --src-instance "TOP/U_MID/U_SRC" --dst-instance "TOP/U_DST"
```

也可以给候选编号，或唯一的例化名。源码中同一父模块内多个语句重用例化名时，候选路径会加上 `@编号`，用于区分源码位置；它是工具的选择标识，不是 HDL generate 层级名称。

多个实例共用 module 定义，预览展示定义级影响及其全部源码引用。未选位置的新增 input 显式接全零，新增 output 显式悬空。后续连接可使用此前的默认绑定；原有非空绑定不会被覆盖。同一目标不能被不同源占用，共用父模块中出现源码级绑定冲突时也会拒绝。

同一 module 被不同父模块类型例化的连接路径，按 PLAN 的 1.0 边界明确拒绝。

### 下标

```powershell
python EasyConnect.py 2 hierarchy.json add "SRC.sig[i]" DST.recv -w 8
```

`[i]` 是源模块直接父层绑定的下标，生成 `.sig(sig[i])`；新建源端口是标量，父层及更高层传输整根 8 bit 总线。目标端下标规则对应，例如 `DST.recv[j]` 生成目标父层的 `.recv(bus[j])`。多维下标依次选择 packed 维度，确定的 part-select 也可以使用。

本版不识别、不展开 for/generate，不检查循环次数、下标范围或多驱动，也不生成仲裁、拼接或 lane 配对逻辑。只修改可定位的例化语句，保留周围代码。用户负责索引在父层的可见性。祖先端点和同作用域局部连接中，没有参与路由的直接父层绑定时，父层下标会明确报错。

## 删除、修改和查询

每次 add 返回独立连接 ID，例如 `c0001`。

```powershell
python EasyConnect.py 2 hierarchy.json list
python EasyConnect.py 2 hierarchy.json rm c0001
python EasyConnect.py 2 hierarchy.json mv c0001 --src SRC.new_sig --dst DST.new_recv -w 16 -c "renamed"
```

mv 保持 ID；没有给出的宽度、注释、端点和实例位置沿用原值。同一个 module 内只改信号名时，保留已选实例。换 module 时重新选择实例。rm 也支持用原始源、目标端点定位唯一连接。

JSON 中的 `_easyconnect` 保存连接、资源引用、默认绑定及编辑前后片段；请保留该 JSON。删除一条连接会保留其他连接使用的共用资源，并恢复原有空绑定。工具生成的信号若已被人工业务代码使用，删除连接时保留局部 wire 并提示。人工修改受管片段时拒绝覆盖并展示差异；新增驱动、备注等不涉及受管片段的修改会保留。

所有操作先规划、检查并显示 diff。`--dry-run` 不写入 RTL 或 JSON。提交前再次核验文件，先准备新文件及回滚副本，再统一替换；写入失败恢复此前状态。更新后的 JSON 会刷新源码校验和行号，编辑依赖重新解析的源码，不直接使用旧行号写入。

原始 JSON 与未受管源码不一致时，应重新执行建图命令。重新建图到同一 JSON 会保留连接归属记录。连接命令使用同路径 `.lock` 文件排除同时写入；进程异常退出后，确认没有运行中的连接命令，再移除遗留的锁。

## 测试和验收

`test_cases/` 是只读 golden。连线工具拒绝写入其中的文件。所有测试会复制三个 case 及跨 case 库依赖到 `test_result/`，最后检查 golden 内容未变。

```powershell
# 零依赖功能测试
python tests/test_rtlgraph.py
python tests/test_easyconnect.py

# 三个 case 的完整建图、可视化和 add/mv/rm 验收
python tests/run_acceptance.py

# 可选独立 SystemVerilog 编译检查，仅用于开发验收
python -m pip install --target test_result/_tools pyslang
python tests/run_acceptance.py --compile
```

验收产物包括修改后的 RTL 副本、层级 JSON、HTML、diff、功能测试日志和编译诊断。最新产物位置汇总在 `test_result/latest_verification.json`。

独立编译检查使用 [slang 的 Python 接口](https://www.sv-lang.com/user-manual.html)。工具运行不依赖 slang。原始 case 本身存在编译错误，因此验收同时报告原始错误和连线后新增错误；合法小工程另行验证编译通过，不把“源码编辑成功”等同于“整个原始工程编译通过”。
